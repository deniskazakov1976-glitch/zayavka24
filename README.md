# BotAvitoTelegram — ИИ-менеджер продаж для Авито и Telegram

Готовая платформа для запуска бизнеса по внедрению ИИ-продавцов в РФ (без зарубежных карт и без ежемесячной оплаты No-Code конструкторам).

## Главные возможности

- **Мультибот: свой Telegram-бот на каждого клиента.** Каждый клиент (тенант) подключает свой токен от @BotFather — диалоги идут от его имени, с его брендом. Боты работают параллельно в одном процессе, падение одного не трогает остальные.
- **Кабинет клиента с ролями и изоляцией.** Вход по логину/паролю (cookie-сессия), три роли: владелец платформы, админ клиента, наблюдатель. Клиент видит только свои компании, заявки, диалоги и пробелы в знаниях — чужие данные недоступны на уровне SQL-запросов.
- **Веб-панель управления процессами (Dashboard):** доступна в браузере по адресу `http://127.0.0.1:8080/`. Мониторинг ключевых KPI (заявки, сессии, паузы), создание компаний под клиентов с Авито в 2 клика с генерацией персональных ссылок, просмотр переписок и ручная пауза/возобновление диалогов.
- **Автоматическое выявление пробелов и Самообучение (Self-Learning):** бот сам отслеживает вопросы клиентов, которых нет в прайсе и базе знаний, моментально отправляет алерт владельцу в Telegram и выводит вопрос в дашборд. Владелец вводит ответ один раз и нажимает «Обучить бота в 1 клик» — ответ мгновенно сохраняется в базу знаний навсегда!
- **Один Telegram-бот = бесконечное число персональных демо:** каждому потенциальному клиенту отправляется своя ссылка `https://t.me/<ваш_бот>?start=<slug_компании>`. Бот мгновенно перевоплощается в старшего мастера именно его компании с его прайсом и адресом.
- **Работает в РФ без VPN:** поддерживает **ProxyAPI.ru**, **VseGPT.ru** и **Polza.ai** (`gpt-4o-mini`) с оплатой через СБП/РФ-карту.
- **Умный сбор заявок:** бот сам извлекает телефон, марку авто и суть запроса (через OpenAI tool calling + резервный regex по РФ-номерам) и мгновенно шлёт карточку заявки владельцу в Telegram.
- **Прямая интеграция с Avito Messenger API:** вебхук `/webhook/avito` + **автопауза**, если владелец сам зашёл в чат Авито и ответил клиенту вручную.
- **Горячее добавление компаний:** создавайте компании прямо через веб-интерфейс или скопируйте `companies/_template.yaml` — перезапуск не нужен.

## Быстрый старт за 5 минут

### 1. Установите зависимости
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. Настройте `.env`
Скопируйте `.env.example` в `.env` и заполните 4 поля:
- `LLM_API_KEY` — ключ с **ProxyAPI.ru** или **VseGPT.ru**
- `TELEGRAM_BOT_TOKEN` — токен от **@BotFather**
- `ADMIN_IDS` — ваш Telegram ID (можно узнать у `@userinfobot`)
- `DEFAULT_NOTIFY_CHAT_ID` — ваш Telegram ID или ID группы для заявок

### 3. Запустите бота
Просто дважды кликните по файлу **`start.bat`** (он автоматически откроет панель управления в браузере и запустит Telegram-бота):
```powershell
.\start.bat
```
*(Или вручную: `python main.py`)*

### 4. Проверьте демо
1. Откройте вашего бота в Telegram и нажмите `/companies` — бот пришлёт готовые ссылки для демо:
   - `demo_detailing` («БлескАвто Детейлинг», Москва)
   - `demo_bodyshop` («АвтоКузов Про», Санкт-Петербург)
2. Перейдите по ссылке и напишите: *«Сколько стоит оклеить капот и фары на BMW X5?»*.
3. Оставьте тестовый номер телефона (например, `+7 999 123-45-67`) и убедитесь, что заявка мгновенно пришла в ваш чат уведомлений.

## Команды в Telegram

- `/start` или `/start <slug>` — начать диалог от имени выбранной компании
- `/reset` — сбросить историю текущего диалога
- `/companies` (или `/admin`) — список всех компаний и персональные ссылки для клиентов *(только админ)*
- `/reload` — перечитать YAML-файлы из `companies/` без перезапуска *(только админ)*
- `/leads` — последние 10 собранных заявок *(только админ)*
- `/pause <chat_id>` / `/resume <chat_id>` — ручная пауза/возобновление ИИ в чате *(только админ)*

## Подключение боевого Авито клиента

Теперь подключить боевой аккаунт Авито Pro можно прямо из браузера через вкладку **«⚡ Подключение Авито Pro»** в дашборде `http://127.0.0.1:8080/`:
1. В кабинете клиента Авито Pro («Интеграции / Для разработчиков») скопируйте `client_id`, `client_secret` и `user_id`.
2. Вставьте их в форму во вкладке «Подключение Авито Pro» и нажмите кнопку **«🔌 Проверить связь с Авито API»**.
3. Укажите компанию по умолчанию и нажмите **«💾 Сохранить настройки Авито»** (настройки автоматически сохранятся в `.env`).
4. Нажмите **«🌐 Зарегистрировать Webhook в Авито»** для автоматической привязки вебхука к вашему публичному HTTPS-домену.

## Мультибот и кабинет клиента

### Как добавить нового клиента (2 минуты)

1. Создайте бота у **@BotFather** (`/newbot`) — получите токен вида `123456:AA...`.
2. Войдите в кабинет владельцем платформы → вкладка **«Клиенты и боты»**.
3. Заполните форму «Новый клиент»: slug, название, **токен бота**, Telegram ID владельца (куда слать заявки), логин и пароль администратора клиента.
4. Нажмите «Создать клиента» — бот сразу запустится, в таблице появится его `@username`.
5. Передайте клиенту адрес кабинета, его логин и пароль. Дальше он сам создаёт компании во вкладке «Компании и ссылки».

Клиент без своего бота **не получает демо-ссылку** — платформенный бот не показывает чужие компании.

### Роли

| Роль | Что может |
|---|---|
| `platform_admin` | всё: все клиенты, создание/удаление тенантов, токены ботов, настройки Авито |
| `client_admin` | только свой клиент: компании, заявки, диалоги, обучение бота, паузы, свои наблюдатели |
| `client_viewer` | только чтение: заявки, диалоги, статистика (изменения — 403) |

### Безопасность

- Пароли — `PBKDF2-HMAC-SHA256`, 260 000 итераций, соль на пользователя.
- Сессия — случайный токен в cookie `HttpOnly` + `SameSite=Lax` (+`Secure` за HTTPS), срок 72 часа, хранится в таблице `user_sessions`, отзыв через «Выйти».
- Защита от брутфорса: 8 неудачных попыток с одного IP → блокировка на 10 минут.
- Изоляция данных выполняется в SQL (`company_slug IN (...)`), а не фильтрацией на фронте.
- Совместимость: HTTP Basic (`DASHBOARD_USER`/`DASHBOARD_PASSWORD`) продолжает работать для API и скриптов.

### Схема БД (миграция 5)

`tenants` (клиент + токен + владелец) → `users` (логин, хеш, роль, tenant_slug) → `user_sessions` (токен, срок) →
`backup_runs` (история и целостность бэкапов) → `llm_usage` (учёт токенов и рублей) →
`model_prices` (тарифы за 1k токенов) → `plans` (лимиты и квоты) → `onboarding` (состояние мастера запуска).

## Новые модули (Версия 2.2 Enterprise)

### Блок A. Автоматические бэкапы и Deep Healthcheck
- **Горячие бэкапы SQLite:** создаются через нативный `sqlite3.backup()` без блокировки чтения и записи. Упаковываются в zip вместе с YAML-конфигами `companies/` и ротируются (`BACKUP_KEEP`, по умолчанию 14 копий).
- **Первый бэкап — сразу при старте**, дальше каждые `BACKUP_INTERVAL_HOURS` (по умолчанию 6 ч). Настройки: `BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP`, `BACKUP_DIR`.
- **Выгрузка за пределы сервера:** `BACKUP_REMOTE=telegram` отправляет архив в чат `DEFAULT_NOTIFY_CHAT_ID` (документом, лимит Bot API 50 МБ). `BACKUP_REMOTE=local` — только локальные копии.
- **Ручной запуск:** `docker exec botavitotelegram-app-1 python scripts/_run_backup_once.py`.
- **Глубокий мониторинг `/health/deep`:** возвращает JSON с задержкой SQLite, статусом каждого бота, свободным местом на диске, очередью и возрастом последнего бэкапа. HTTP-код: **503 при `status=fail`** (нет БД или критически мало места), иначе 200; `degraded` (мёртвый бот, устаревший бэкап, диск выше `DISK_WARN_PCT`) отдаётся с кодом 200.
- **Telegram AlertManager:** алерты о сбоях с антифлуд-кулдауном (`ALERT_COOLDOWN_MINUTES`, по умолчанию 30) на тип события; отключается через `ALERTS_ENABLED=false`.

### Блок B. Учёт расходов и квоты LLM
- **Учёт токенов в реальном времени:** перехват `response.usage` (prompt_tokens, completion_tokens, total_tokens) в `LLMService` без дополнительных HTTP-запросов.
- **Тарификация в рублях:** таблица `model_prices`, цены за 1k токенов ввода и вывода.
  При старте приложение автоматически добавляет цену для модели из `LLM_MODEL` (значения из
  `LLM_PRICE_PROMPT_RUB_PER_1K` / `LLM_PRICE_COMPLETION_RUB_PER_1K`), если её там ещё нет —
  **поэтому стоимость не бывает нулевой «по умолчанию»**. Существующую цену авто-сид не перезаписывает;
  поменять можно через `POST /api/model-prices` или вкладку «Расходы».
- **Квоты и тарифы клиентов (`QuotaService`):**
  - Тарифы в БД: `basic` (0 ₽, 1000 сообщений/мес), `pro` (2990 ₽/мес, 5000 сообщений), `internal` (без лимитов). Список и цены редактируются через `POST /api/plans`.
  - Неизвестный тариф у клиента трактуется как `basic`, а не как безлимит.
  - Soft warning (80 % лимита): уведомление администратору платформы в Telegram.
  - Hard limit (100 %): вызов LLM не выполняется, клиент получает вежливый ответ, событие пишется в `guard_events` с `blocked_terms='quota'`. Лимит проверяется и для **текста, и для фотографий**.
- **Вкладка «Расходы» в дашборде:** сообщения, токены, стоимость и процент от лимита за период (день/неделя/месяц), разбивка по моделям; для владельца платформы — сводка по всем клиентам.

### Блок C. Интерактивный Onboarding Wizard
- **Мастер настройки за 5 шагов (`/onboarding`)**, вход — кнопка **«Мастер настройки»** в шапке дашборда:
  1. *Бизнес и город:* название, город, адрес, график работы (тумблер «Круглосуточно 24/7»).
  2. *Парсер прайс-листа:* вставьте текст из WhatsApp, Excel, 2GIS или Word. Распознаются форматы: `25000`, `25 000`, `25.000`, `15 000,50`, `15k`, `от 12 000 р`, `8 000 рублей`, диапазон `35 000 - 45 000`. **Дефис внутри названия** («Полировка-экспресс 5000») сохраняется как часть названия.
  3. *Преимущества и спецпредложения:* скидка на первый визит, гарантии, материалы.
  4. *Тестовый диалог прямо в мастере* — пообщаться с ботом до публикации.
  5. *Готово:* компания создаётся с транслитом слага (`slugify_russian`), выдаётся персональная Telegram-ссылка.
- **Автопереход:** клиент без компаний и без завершённого онбординга при входе в `/` перенаправляется на `/onboarding`.

### Как проверить второго (клиентского) бота вживую

1. **Создайте бота**: Telegram → `@BotFather` → `/newbot` → имя и username (должен кончаться на `bot`).
   Скопируйте токен вида `123456789:AAH...`.
2. **Свой Telegram ID**: напишите `@userinfobot` — он пришлёт число (например `1386305443`).
3. **Заведите клиента**: кабинет → войти как владелец платформы → вкладка **«Клиенты и боты»** →
   форма «Новый клиент»:
   - slug: `test-client`
   - название: `Тестовый клиент`
   - токен: вставьте токен из шага 1
   - Telegram ID владельца: число из шага 2 (сюда будут приходить заявки)
   - логин и пароль администратора клиента (мин. 8 символов)
4. **Проверьте, что бот поднялся**: в таблице появится `@ваш_бот` и бейдж **«работает»**.
   Если бот не отвечает Telegram — будет «токен есть, бот не отвечает».
5. **Создайте компанию от лица клиента**: выйдите (`/logout`) → войдите логином клиента →
   вкладка «Добавить компанию» → заполните и сохраните.
6. **Проверьте ссылку**: вкладка «Компании и ссылки» → появится ссылка
   `https://t.me/ваш_бот?start=<slug>`. Откройте её в Telegram.
7. **Напишите боту** «Сколько стоит полировка?» — должен ответить от имени компании клиента,
   а карточка заявки прийти вам в Telegram (ID из шага 3).
8. **Проверьте изоляцию**: оставаясь в кабинете клиента, убедитесь, что в «Лидах» и «Диалогах»
   только его данные, а платформенные компании не видны.

Если на шаге 4 бот не поднялся — смотрите логи:

```bash
ssh aeza-vps "cd /opt/BotAvitoTelegram && docker logs --tail 50 botavitotelegram-app-1 | grep -i 'бот\\|error'"
```

Типичные причины: токен скопирован с пробелом, бот удалён в BotFather, либо второй экземпляр
того же бота уже запущен где-то ещё (Telegram разрешает только один `getUpdates`).

## Контроль версий (git)

Проект под git. Что **не** попадает в репозиторий (см. `.gitignore`): `.env` с токенами,
`data/` с базой и персональными данными клиентов, архивы бэкапов, `.venv`, артефакты инструментов.

```powershell
git log --oneline                 # история
git status                        # что изменено
git diff                          # что именно изменено
git tag -l                        # релизы
```

**Перед каждым деплоем** фиксируйте состояние:

```powershell
git add -A
git commit -m "что изменили"
```

**Откат к рабочей версии** (если после правок что-то сломалось):

```powershell
git stash                         # убрать незакоммиченные правки
git checkout <hash-или-тег>       # вернуться к известной рабочей версии
# либо, если правки уже закоммичены:
git revert <hash>                 # отменить конкретный коммит, сохранив историю
```

После отката не забудьте передеплоить — на сервере код обновляется только деплоем:

```powershell
tar -czf $env:TEMP\botapp.tgz --exclude="__pycache__" app main.py requirements.txt tests README.md .env.example
scp $env:TEMP\botapp.tgz aeza-vps:/root/botapp.tgz
Get-Content -Raw scripts\_deploy_multibot.sh | ssh aeza-vps "bash -s"
```

Перед распаковкой `scripts/_deploy_multibot.sh` сам складывает архив кода и копию БД
в `/root/backups/` на сервере — это вторая линия отката, независимая от git.

**Если планируете публиковать репозиторий** (GitHub/GitLab): сначала смените пароль
`DASHBOARD_PASSWORD`, токен бота через `@BotFather` и `AVITO_CLIENT_SECRET` — они лежали
в `.env`, но старые значения уже засветились в переписке и в копиях на сервере.
